# 硬件评审：这辆车的设计缺陷与改进清单

> 评审对象：2026 校赛 STM32 循迹智能车（2S 18650 / TB6612 / 8 路红光灰度 + CD4051 / STM32F103C8T6 兼容片）
> 评审依据：**不是看图纸猜的**，而是这套车在 2026-11-10 ~ 11-21 十二天调试中真实发生过的故障与实测数据。
> 结论标注方式：🔴 已造成事故 · 🟡 潜在风险（未爆但有明确机理）· ⚪ 设计取舍（不是错，是代价）

---

## 1. 供电系统（最该改的一条）

### 1.1 现状

```
2S 18650 (7.4V) ── KCD1 开关 ── KF128 端子 ─┬─ LM2596 ── 5.00V ── STM32 5V 脚 ── AMS1117 ── 3.3V
                                            └─ TB6612 VM（电机直取母线）
```

问题在于**逻辑与功率共用一条母线，中间只有一个 LM2596，没有任何储能元件**。

### 1.2 为什么这是缺陷（机理 + 数字）

- **堵转电流**：两只 TT 马达堵转各约 1.2–1.5A，合计接近 3A（TB6612 单通道连续 1.2A、峰值 3.2A，已经在边缘）。
- **电池内阻**：2S 18650 单节 30–60mΩ，两节串联 60–120mΩ。3A × 100mΩ ≈ **0.3V 瞬时压降**，再加上杜邦线/端子的接触电阻，母线从 7.4V 掉到 6.8V 以下很常见。
- **LM2596 的响应**：开关频率 150kHz，负载阶跃响应在几十 µs 级别，对 ms 级的 PWM 切换**来不及**补偿，5V 轨会跟着抖。
- **AMS1117 的 PSRR**：100kHz 附近只有 40dB 左右。50mV 纹波 → 输出约 0.5mV。
- **ADC 的 LSB**：3.3V / 4096 = **0.8mV**。也就是说纹波幅度和 ADC 最小分辨单位同量级，末位读数一定在跳。

### 1.3 现场证据

- 2026-11-10 出现「**只有蓝灯亮起时小车才动，蓝灯几秒闪一次，车就几秒动一次**」——蓝灯是 200ms 心跳 LED，现象与"反复复位→启动窗口→擦 Flash→跑几十毫秒→再复位"完全吻合。
- 2026-11-12 提速到 999 占空比冲刺时，`** STALL` 与偶发复位同时出现。

### 1.4 改进方案

| 措施 | 做法 | 效果 |
|---|---|---|
| 分域供电 | 从 KF128 端子处**分别**引出两条线：一条给 TB6612 VM，一条给 LM2596 | 电机浪涌不再经过逻辑电源 |
| 母线储能 | VM 处并 **470–1000µF / 16V 电解 + 0.1µF 陶瓷** | 吸收 PWM 尖峰，压降从 0.3V 降到 0.05V 级 |
| 逻辑侧滤波 | 5V 后串 **10µF + 0.1µF**；能换 LDO（AMS1117 反而比 LM2596 干净）就更好 | ADC 纹波降到 LSB 以下 |
| 欠压监测 | 电池正极 → **100k/33k 分压** → `PB0`(ADC1_IN8) | 上电打印电压，< 6.6V 拒绝起跑 |
| 保护 | 串 **5A 保险丝** + 反接保护（P-MOS 或肖特基） | 反接不烧板 |

> 分压计算：7.4V × 33/(100+33) = 1.84V，满电 8.4V → 2.08V，都在 3.3V 内，安全。

## 2. 接线与机械连接

### 2.1 问题

- 电机线、编码器线、传感器排线**全部是用杜邦线**插在排针上，再用扎带绑在会振动的车架上。
- 编码器 4 根线紧贴电机两根线走，没有双绞、没有屏蔽。

### 2.2 现场证据（🔴 实际咬到）

2026-11-16 串口日志：

```
[L4] cm=40 turn=-90
d=97/400mm sp=340 e=0 pid=0 v=0 n=0
      L pwm=340 dL=0mm  R pwm=340 dR=195mm
      !! LEFT wheel: pwm>0 but no encoder motion (wire/motor/driver/B-channel)
```

软件给左轮 34% 占空比、方向位与右轮**完全对称**（`motor_gpio_dir()` 把 PB12–PB15 四脚都配了推挽），但左编码器零计数。

后来只是**重烧了一次固件、顺手整理了一下线**，左轮就恢复了 —— 典型的接触不良，不是代码问题。

### 2.3 改进

1. 电机线、电源线**焊接**（20AWG 硅胶线），编码器线改 26AWG 并**双绞**；
2. 每根线焊点处做**应力释放**（热缩管 + 扎带固定在车架上，不靠焊点受力）；
3. TB6612 的 `IN1/IN2/BO1/BO2` 直接焊到转接板，去掉排针；
4. TB6612 贴一片小散热片（1A 连续时结温会明显上升）。

## 3. 循迹传感器与模拟前端

### 3.1 现状

8 路红光灰度模块（数字/模拟两用），板上自带 **CD4051 八选一模拟开关**：AD0/AD1/AD2 选通道，OUT 是公共输出 → 接 `PA3`(ADC1_IN3)。

### 3.2 为什么这是缺陷

| 机理 | 影响 |
|---|---|
| 4051 导通电阻 RON ≈ 125Ω（5V），随温度漂移 | 8 个通道的增益不完全一致，压线位置会有系统性偏差 |
| 通道切换时**电荷注入**（~10pC） | 亮通道的信号会渗到相邻通道，白线在 X3 时 X4 也会跟着虚高 |
| 每次切换要等 ~2µs 稳定 | 8 路一轮 ≈ 46–64µs，占 2ms 控制环的 3% |
| 公共 OUT 是**单点故障** | 那一根线接触不良 → 8 路全废（实际遇到过 `adc now: 4095 ×8`） |
| 板载 LED 指示灯 8 颗常亮 | 恒定多出 ~120mA 负载，直接加剧第 1 节的压降 |

**关键事实**：STM32F103C8T6 有 8 个 12 位 ADC 通道（`PA0–PA7` = IN0–IN7），**本来可以一对一接完 8 路**，用 4051 省下的只是 4 根线，代价却是上面 5 条。

### 3.3 改进

1. **8 根信号线直接进 PA0–PA7**，`ADC1->SQR3 = ch` 逐通道扫描（本仓库 v0.6.0 就是这种写法，可直接参考）；
2. 每根线串 **100Ω + 100nF 到地**（RC 低通，fc≈16kHz），滤掉电机 PWM 的 1kHz 及其谐波；
3. 探头加**遮光罩**（黑胶套/3D 打印，底部开口），把安装高度容差从 5–8mm 拉宽到 15mm 以上；
4. 若换模块，优先选**带 I2C/数字输出的灰度阵列**，把模拟噪声问题整体推给模块厂商。

## 4. 编码器与运动学

### 4.1 现状

- 左轮：`TIM4` 硬件编码器模式（PB6/PB7），四倍频由硬件完成；
- 右轮：`EXTI9_5` + 软件状态机 `Q[4][4]`（PB8/PB9），每次边沿进中断累加；
- 读取方式：读 `TIM4->CNT` / `enc_r` 后**立即清零**（无硬件锁存）。

### 4.2 缺陷

| 问题 | 后果 | 是否值得改 |
|---|---|---|
| 左右计数方式不对称 | 软件四倍频占 CPU（2ms 环内多次中断），且丢边沿时两轮不等 | ⚪ 建议都改硬件编码器模式 |
| 读后清零 | 读与清之间有 1 个 count 的窗口，最坏各少 1 | ⚪ 可忽略（1 count ≈ 0.37µm... 实际 1/2700 cm = 3.7µm） |
| 16 位回绕 | 32767 / 2700 ≈ **12.1cm**，超过就翻负 | ⚪ 当前每 2–5ms 取一次数，到不了 12cm，安全 |
| 装在电机轴而非轮轴 | 齿轮间隙不计入 | ⚪ 影响 <1% |

### 4.3 机械层面的真问题（最关键）

`TURN_SCALE = 0.68` 不是代码 bug，是**机械在告诉你"理想几何不成立"**：

- 几何计算：90° 原地转，单轮弧长 = π × 16.75 / 4 = **13.15cm**；
- 实测标定后，仅需 **13.15 × 0.68 = 8.94cm** 就转到位；
- 差值 32% 全部消耗在**轮胎刮擦**上（轮距窄、轴距长、轮胎硬、地面是喷绘布）。

这意味着：**任何纯里程开环的转弯都不可靠**，必须靠"转完用线找回来"闭环（本项目 v0.11.0 起就是这么做的）。

改进方向（不一定要做）：换低摩擦万向轮/窄胎、缩短轴距、或者直接在转弯时用**一角速度闭环**（IMU）。

## 5. 主控与外设资源

### 5.1 兼容片的 ADC 坑（🔴 花了一整天）

现象：ADC 读回恒为 4 或 4095，遮住传感器毫无变化，`SR=16`（STRT 卡在 1）、`EOC` 永不置位。

根因：这颗 `idcode=0` 的片子（CS32/APM32 一类兼容品）**只写 `SWSTART` 不启动转换**，必须写
`EXTSEL = 111` + `EXTTRIG` 再 `SWSTART`，并且初始化时 `ADON` 后要等 10ms、校准不能死等。

```c
ADC1->SQR3 = ch;
ADC1->CR2 |= (7u << 17) | ADC_CR2_EXTTRIG;   /* EXTSEL=111, EXTTRIG */
ADC1->CR2 |= ADC_CR2_SWSTART;
busy_us(60);
return ADC1->DR & 0x0FFFu;                    /* 不信 EOC，定时读 */
```

**改进**：正式比赛或产品用它之前，先跑一遍 `vref`（内部 ch17）自检 —— 读不到 ~1450 就说明 ADC 内核有兼容问题。预算允许就换**原装 STM32F103**或 F4（￥25 换一天时间）。

### 5.2 引脚冲突（🟡 设计时就该避免）

`PA11` 同时是 **USB D−** 和 **TIM1_CH4**，本项目用它输出左轮 PWM。后果：

- 插着 USB 调试串口时，1kHz PWM 会往 USB 线上打干扰；
- USB 上拉/枚举过程也会改变该引脚电平，极端情况下左轮抖一下。

**改进**：左轮 PWM 挪到 `TIM3_CH1/CH2`（PB4/PB5）或 `TIM2` 的通道，PA0–PA7 留给 ADC，PA11 留给 USB。

### 5.3 无参数存储（🟡）

标定值（`blk=4095 / wht=175`、`TURN_SCALE`）只存 RAM，每次上电回默认。比赛换场地要重标，误烧一次就全丢。

**改进**：占用 Flash 最后一页（1KB）存一个结构体 + CRC，上电读、标定后写。本仓库 `route_follow.c` 里的黑匣子日志已经实现了"擦页/写/回读校验"，直接复用即可。

## 6. 调试与观测（决定调试效率的一环）

| 问题 | 实际代价 |
|---|---|
| 没有蓝牙/WiFi 模块 | 跑车全程看不到任何数据，只能"跑完再看" |
| USB-TTL 线只有几厘米 | 边跑边接根本不可能，`x`/`m` 这类"中途按键"设计全部作废 |
| 黑匣子日志只在 `route_follow.c`，最终版 `analog_route.c` 没移植 | 这次比赛是**纯盲跑**拿到 1:35；若移植了，标定至少省半天 |

**改进**（按性价比排序）：
1. **Flash 黑匣子**（￥0，纯代码）：跑的时候不接线，跑完插线 → 上电 1 秒内发 `d` → 导出 CSV；
2. ESP8266/蓝牙 HC-05（￥10–30）：实时看 `e / pid / v`，调 PID 时能直接看到震荡；
3. 板载一颗 RGB LED 做"状态灯"（绿=在线、黄=找线、红=丢线超时），赛场上不用接线也知道车怎么了。

## 8. 一句话总结

> 这辆车的**控制软件做到了 30.2cm/s 完赛**，但**硬件在每一层都留了一个"会在关键时刻咬人"的口子**：
> 供电共用母线（复位）、杜邦线（假故障）、4051 复用（单点故障）、兼容片（ADC 不启动）、
> 无存储（参数丢失）、无无线（盲跑）。
> 软件层面靠"每段自愈 + 视觉找线"把这些硬件不确定性吸收掉了 —— 这也是为什么最终能拿 1:35，
> 但**下一版如果按第 1/2/12 条改硬件，同样的软件能稳得多，也快得多**。
